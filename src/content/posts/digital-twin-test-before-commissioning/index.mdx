## Digital Twin ในมุมคนทำ PLC

ไม่ต้องคิดถึงโรงงานเสมือนสามมิติราคาแพงครับ สำหรับคนทำ Control
Digital Twin คือ **โมเดลของกระบวนการ ที่ตอบสนองเหมือนของจริงมากพอ** จนเอาคอนโทรลเลอร์ตัวเดิมมาทดสอบด้วยได้

หัวใจของมันมีแค่ 3 อย่าง

1. **โมเดลที่วัดมาจริง** ค่า gain, time constant และ dead time ต้องได้จาก step test บนเครื่องจริง ไม่ใช่เดาเอา
2. **คอนโทรลเลอร์ตัวเดียวกัน** ห้ามมีเวอร์ชันสำหรับ simulation กับเวอร์ชันหน้างานแยกกัน
3. **การเชื่อมต่อที่สลับได้** ไปที่โมเดลหรือไปที่เครื่องจริงด้วยสวิตช์ตัวเดียว

## ชุดทดลองที่เราทำ: S7-1500 + Simulink + OPC UA

ชุดฝึกนี้เป็นงานสอนวิชา Process Control ร่วมกับอาจารย์มหาวิทยาลัย
เรารับผิดชอบฝั่ง Simulink กับการเชื่อม OPC UA ส่วนโปรแกรม PLC บนเครื่องมีอีกคนดูแล

ตัวเครื่องมีลูปปั๊ม 1 ลูป ประกอบด้วย Level transmitter, Flow transmitter, Control valve และปั๊มที่ขับด้วยอินเวอร์เตอร์ ควบคุมด้วย **S7-1500** ที่เขียนใน TIA Portal V17

### ทำไมเลือก OPC UA

S7-1500 มี **OPC UA Server ในตัว** ฝั่ง MATLAB ใช้ Industrial Communication Toolbox ต่อเข้าไป browse หา tag แล้วอ่านเขียนด้วย**ชื่อ tag** ได้เลย

- ไม่ต้องซื้อฮาร์ดแวร์หรือ license เพิ่ม
- ไม่ต้องเขียนโปรแกรม PLC ชุดที่สองไว้คุยกับ Simulink
- ชื่อ tag เดียวกันใช้ได้ในทุกโมเดล เพราะทำ **Tag contract** ไว้ชัดเจนว่าแต่ละลูปมี SP, PV และ Output อะไรบ้าง

## Model ก่อน Tune

ลูปสองตัวบนเครื่องนี้พฤติกรรมต่างกันมาก

| ลูป | โมเดล | พฤติกรรม |
|---|---|---|
| Level | Integrating · `G(s) = K/s` | ไม่มีจุดนิ่งในตัวเอง ถ้าเข้ามากกว่าออก ถังก็จะเต็มไปเรื่อย ๆ |
| Flow | FOPDT · `G(s) = K·e^(−θs)/(τs + 1)` | ตอบสนองเร็ว แต่มี dead time |

ค่าพารามิเตอร์ทั้งหมดมาจาก **step test บนเครื่องจริง** นี่คือเหตุผลที่ค่าจูนที่หาได้ใน Simulink เอาไปใช้กับเครื่องจริงได้
ถ้าโมเดลมาจากการเดา Twin ก็จะกลายเป็นแค่เกมที่ทำให้เรามั่นใจผิด ๆ

## ลองเอง: จูน PID บน Twin

ตัวจำลองด้านล่างเป็นถังแบบ Integrating ที่มี dead time แบบเดียวกับลูป Level
Setpoint จะกระโดดจาก 50 % ไป 75 % ที่วินาทีที่ 10 และ**ห้ามชน HH 85 %**
ค่าเริ่มต้นจูนแรงเกินไปเจตนาให้ถังล้น ลองหาค่าที่ผ่านทุกเกณฑ์ดูครับ

<TankSim />

สิ่งที่เห็นในตัวจำลองนี้คือเรื่องจริงของ Integrating process ครับ
**Kp สูงกับ Ti สั้น** ทำให้ตอบสนองไว แต่ Overshoot พุ่ง ส่วน**จูนอ่อนเกินไป**ก็ปลอดภัย แต่นิ่งช้าจนตกเกณฑ์ Settling time
การหาจุดสมดุลแบบนี้ใน Twin ใช้เวลาไม่กี่นาที ถ้าไปลองบนเครื่องจริง อาจต้องเสียน้ำไปหนึ่งถัง

## Cascade: จูนลูปในก่อนเสมอ

บนเครื่องจริงใช้ **Level–Flow cascade** ลูป Level ข้างนอกไม่ได้สั่งวาล์วเอง แต่**ตั้ง Setpoint ให้ลูป Flow** แล้วลูป Flow ถึงจะขับ Control valve

ลำดับที่ใช้เสมอคือ

1. จูน **Flow (ลูปใน)** ก่อน ให้เร็วและนิ่ง
2. ค่อยจูน **Level (ลูปนอก)** ให้ช้ากว่าลูปในชัดเจน
3. ใส่ disturbance เดียวกันกับทั้ง single-loop และ cascade แล้วเทียบผลบนกราฟ

## สิ่งที่ Twin มักจับได้ก่อนลงหน้างาน

ปัญหาเหล่านี้เจอบ่อยในงาน Commissioning ทั่วไป และเป็นประเภทที่ Twin ช่วยให้เจอได้เร็วมาก

- **Scaling ผิดหน่วย** PV เป็น 0–100 % แต่ฝั่งหนึ่งคิดเป็น 0–27648 คอนโทรลเลอร์จะเพี้ยนทันทีตั้งแต่วินาทีแรก
- **ทิศทาง Action กลับด้าน** Direct กับ Reverse สลับกัน วาล์วจะเปิดสวนทางกับที่ควรเป็น
- **ลืม Anti-windup** หลังวาล์วตันสุดแล้วกลับมา ลูปจะ overshoot แรงผิดปกติ
- **Tag ไม่ตรง Contract** ชื่อหรือ data type ฝั่ง PLC กับ Simulink ไม่ตรงกัน ซึ่งเจอใน Twin ได้ภายในไม่กี่วินาที

ทุกข้อนี้ถ้าไปเจอตอนเครื่องหมุนจริงต่อหน้าฝ่ายผลิต จะกลายเป็นทั้งความเสี่ยงและความเครียด
แต่ถ้าเจอใน Twin มันก็เป็นแค่บรรทัดหนึ่งใน Test log ครับ

## เครื่องมือแบบไหนก็เริ่มได้

ไม่จำเป็นต้องมี MATLAB เสมอไป เลือกตามงานได้เลย

- **PLCSIM Advanced** ทดสอบโปรแกรม S7-1500 ได้โดยไม่ต้องมีฮาร์ดแวร์

## สรุป

1. **Twin ที่ดีมาจากข้อมูลจริง** step test ก่อนแล้วค่อยสร้างโมเดล
2. **คอนโทรลเลอร์ตัวเดียว สวิตช์เดียว** ไม่ต้องเขียนโค้ดสองชุด
3. **เคสอันตรายเล่นใน Twin** เคส Safety พิสูจน์บนเครื่องจริง
4. **เขียน Test case ก่อนเขียนโค้ด** แล้วไล่ทีละข้อ นี่คือการคิดเป็นระบบที่จับต้องได้

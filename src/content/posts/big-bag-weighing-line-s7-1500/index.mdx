หลังโรงงานน้ำมันพืชสกัดน้ำมันออกไปแล้ว จะเหลือ **กากพืช (Meal)** และ **เปลือกเมล็ด (Hull)** ออกมาวันละมากครับ
ของพวกนี้ไม่ใช่ของเสีย เพราะเอาไปทำ **อาหารสัตว์** ได้ แต่ต้องบรรจุลง **Big Bag ถุงละราว 1.35 ตัน** ให้น้ำหนักตรงทุกถุง
แล้วส่งออกไปตามคอนเวย์เยอร์ทีละพาเลท

ไลน์นี้ใช้อุปกรณ์ชั่งและขนถ่ายจากผู้ผลิตเฉพาะทาง แต่โรงงานอยากได้ระบบควบคุมที่ **ทันสมัยกว่าเดิมและดูแลเองได้**
งานของเราคือ **เขียนโปรแกรม PLC ขึ้นมาใหม่ทั้งหมด** และ **ออกแบบหน้าจอ HMI เอง** ให้คุมได้ตั้งแต่ Hopper รับวัตถุดิบ
การชั่ง การเติมลงถุง คอนเวย์เยอร์ ไปจนถึงพาเลทเปล่า รวมถึงรับส่งสัญญาณกับตู้ของโรงงานและสถานีบรรจุ Big Bag ด้วย **Hardwire** และ **PUT/GET** ครับ

## ทำไมต้องชั่งใน Hopper ก่อน

ถ้าเติมลงถุงแล้วชั่งไปพร้อมกัน ฝุ่น ถุงที่แกว่ง และแรงกระแทกของวัตถุดิบจะทำให้ค่าน้ำหนักนิ่งยากครับ
ไลน์นี้จึงแยกเป็น 2 จังหวะ คือ **ชั่งในถังชั่งที่วางบนโหลดเซลล์ให้ได้น้ำหนักก่อน** แล้วค่อย **เทลงถุงทีเดียวจนถังว่าง**

1. **เช็คก่อนเริ่ม** วาล์ว FV-31-01 และ FV-31-02 ต้องปิดจริงตาม Limit switch และ Set point ต้องมากกว่า 0
2. **Tare ถังชั่งให้เป็น 0** ถ้า Tare ไม่ได้ จะขึ้น Alarm "Weight tare not ready" ไม่เดินต่อ
3. **FAST** เปิดทั้ง 2 วาล์ว Screw วิ่งเร็ว จนถึง **SP1**
4. **SLOW 1** ปิด FV-31-02 เหลือ FV-31-01 Screw ช้าลง จนถึง **SP2**
5. **SLOW 2** ค่อยๆ เติมช่วงสุดท้าย จนน้ำหนักอยู่ใน **±0.7% ของ Set point** แล้วปิดทุกอย่าง ส่ง **Weigh Finish**
6. รอ **Big Bag Ready** และ **Start Filling** จากสถานีบรรจุ แล้วเปิด FV-31-03 พร้อมเปิด Dust collector
7. พอน้ำหนักกลับมาเป็น **0** รออีก **2 วินาที** ให้ของที่ค้างตกให้หมด แล้วปิด FV-31-03 ส่ง **Filling Finish**

ลองกด **Start** ดูรอบการทำงาน เปลี่ยน Set point แล้วสังเกตกราฟว่าความเร็วเปลี่ยนตรงไหน
จากนั้นลองใส่ Fault ทีละตัว จะเห็นว่าไลน์หยุดที่สเต็ปไหนและ HMI บอกอะไรครับ

<Callout type="tip" title="ของที่ยังลอยอยู่กลางอากาศ">
ตอนปิดวาล์ว วัตถุดิบที่หล่นอยู่ระหว่าง Screw กับถังชั่งยังไม่ถูกนับครับ เราเรียกส่วนนี้ว่า **In-flight**
ถ้ารอจนน้ำหนักถึง Set point พอดีแล้วค่อยปิด ทุกถุงจะเกินเสมอ การแบ่งเป็น 3 สปีดช่วยให้ช่วงท้ายไหลช้าจน In-flight เหลือน้อย
และตัดก่อนถึง Set point เล็กน้อยได้ ตัวเลขในตัวอย่างข้างบนเป็นค่าประกอบการอธิบาย ไม่ใช่ค่าที่ตั้งจริงหน้างาน
</Callout>

## คุยกับเครื่องอื่นด้วยสัญญาณที่ชัดเจน

ไลน์นี้ไม่ได้อยู่ลำพังครับ วาล์วป้อนวัตถุดิบเป็นของตู้ควบคุมของโรงงาน ส่วนสถานีบรรจุ Big Bag มี PLC ของตัวเอง
เราจึงต้องตกลงกันให้ชัดตั้งแต่ประชุมแรกว่า **ใครส่งอะไร เมื่อไหร่**

| จากตู้ฝั่งโรงงานและสถานีบรรจุ → PLC ของเรา | จาก PLC ของเรา → ตู้ฝั่งโรงงานและสถานีบรรจุ |
|---|---|
| Valve Feed Open | Auto Mode Run |
| Big Bag Ready | Safety OK |
| Start Filling | Weigh Finish |
| Start to Transfer | Filling Finish |
| Pallet Supply Ready | Pallet Empty |

สัญญาณที่เกี่ยวกับความปลอดภัย เช่น Safety และสถานะวาล์วป้อน เราเลือกเดินเป็น **Hardwire** เพราะต้องทำงานแม้เครือข่ายมีปัญหา
ส่วนข้อมูลกับ PLC ของสถานีบรรจุใช้ **S7 PUT/GET** ผ่าน Data block เดียวกัน ฝั่งละ 2 ไบต์ของบิตสถานะ ตามด้วย Int และ Real สำรอง
บิตสำคัญคือ `End_of_filling`, `Transfer_big_bag`, `Empty_Pallet_Ready`, `Start_filling_authorization`, `Big_bag_ready_to_be_evacuated`
และค่า `Weight_loaded_in_big_bag` ส่งน้ำหนักจริงของถุงกลับไป ตารางเดียวกันใช้กับสถานีบรรจุทั้ง 3 ชุด เปลี่ยนแค่ Offset ของ Address

<Callout type="safety" title="Health bit ทั้งสองทาง">
บิตแรกของทั้งสองฝั่งคือ `Health_bit` ที่ต้องกระพริบตลอดเวลา ถ้าฝั่งหนึ่งหยุดกระพริบ อีกฝั่งจะรู้ทันทีว่าการสื่อสารขาด
และขึ้น Alarm **Connection Fail** แทนที่จะรอ "Start Filling" ที่ไม่มีวันมา ลองกด Fault "Health bit stopped" ในตัวอย่างข้างบนดูครับ
</Callout>

## คอนเวย์เยอร์และพาเลท

หลังได้ **Start to Transfer** คอนเวย์เยอร์จะพาถุงเต็มออกไปทีละช่วงตาม Photo sensor
เริ่มจากช่วงแรก พอเซนเซอร์ช่วงถัดไปเห็นถุง ก็เปิดช่วงที่สองตาม และ **หน่วง 3 วินาทีก่อนเปิดช่วงที่สาม**
ไม่ให้มอเตอร์ทุกตัวออกตัวพร้อมกัน พอถุงถึงปลายทางจึงตั้งบิต **L2 to transfer** ให้คอนเวย์เยอร์ทางออกที่ใช้ร่วมกับอีกไลน์
ตัดสินว่าจะรับถุงจากไลน์ไหนก่อน

ฝั่งพาเลท เราส่ง **Pallet Request** ไปที่เครื่องจ่ายพาเลท พอได้ **Pallet Ready** ก็เดินมอเตอร์ Magazine และ Dispenser
จนเซนเซอร์ยืนยันว่าพาเลทเข้าที่ แล้วจึงหยุด เป็น Handshake แบบเดียวกับฝั่งการชั่ง คือ **ทุกการเคลื่อนที่ต้องมีคนขอและคนยืนยัน**

## HMI ที่ออกแบบเอง

หน้าจอหลักเป็น **Process overview หน้าเดียว** ที่วางอุปกรณ์ตามตำแหน่งจริงของไลน์ ตั้งแต่ Hopper ลงไปถึงคอนเวย์เยอร์และพาเลท
ช่างดูจอเดียวก็รู้ว่าวัตถุดิบอยู่ตรงไหนและเครื่องรออะไรอยู่

| ส่วนบนหน้าจอ | สิ่งที่ทำได้ |
|---|---|
| Auto / Manual | สลับโหมดด้วย Selector บนจอ ในโหมด Manual สั่งเปิด/ปิดวาล์วทีละตัวได้ด้วยปุ่ม C / O ข้างวาล์ว |
| Set point / Weight actual | ตั้งน้ำหนักที่ต้องการต่อถุง และดูน้ำหนักจริงจากถังชั่งแบบสด |
| สถานะ Hopper | ไฟ HHSL, HSL, LSL และสถานะ Big Bag Ready / Big Bag Full |
| Start / Stop / Reset | ใช้ร่วมกับปุ่มบนตู้ |
| แถบบน | ผู้ใช้ที่ล็อกอิน, Alarm banner, ปุ่ม Acknowledge และชั่วโมงการทำงาน |
| มอเตอร์ทุกตัว | VSD และมอเตอร์บนคอนเวย์เยอร์มีสถานะของตัวเอง ถ้าถูก Isolate จะเป็นสีแดงแยกจาก Fault |

<Callout type="safety" title="Alarm ที่ตกลงกันตั้งแต่ก่อนเขียนโค้ด">
รายการ Alarm ถูกกำหนดในที่ประชุมก่อนเริ่มเขียนโปรแกรมครับ **Safety / Emergency**, **Valve fault** (สั่งแล้ว Limit switch ไม่ตอบ),
**Breaker fault**, **VSD fault**, **Connection fail** และ **Weight tare not ready** ทุกตัวต้องกด **Acknowledge บน HMI**
ส่วนสวิตช์ Isolator หน้ามอเตอร์ เมื่อเปิดจะตัดมอเตอร์ตัวนั้นออกจาก Auto ทันที และแสดงเป็นสถานะ Isolate สีแดง
ช่างที่กำลังซ่อมจะไม่ถูกเครื่องสั่งเดินโดยไม่รู้ตัว
</Callout>

เรายังเขียน **คู่มือขั้นตอนการเดินเครื่องจากหน้าจอ HMI** 12 ขั้น ตั้งแต่เช็ควาล์วและมอเตอร์ให้อยู่ตำแหน่งปิด กด Reset, Start,
เลือก Auto, ตั้งน้ำหนัก จนถึงพาเลทเปล่าเข้ามา พร้อมแยกสีในคู่มือว่าสัญญาณไหนมาจากตู้ฝั่งโรงงาน สัญญาณไหนมาจากตู้ของเรา

## ฮาร์ดแวร์และไทม์ไลน์

- **PLC** S7-1500 CPU 1511-1 PN กับ Remote I/O ET 200SP ทั้ง DI, DQ, AI และ AQ สำหรับสั่งความเร็ว VSD
- **HMI** SIMATIC TP1200 Comfort เขียนด้วย TIA Portal V17 เชื่อมกับ PLC ผ่าน PROFINET
- **ประชุมเริ่มงาน** กลางเดือนพฤษภาคม 2024 สรุปสัญญาณ Exchange, Alarm และกติกาความปลอดภัย จากนั้นส่ง **Flowchart และ Text file**
  ของทุกไลน์ให้ลูกค้ารีวิว (ไลน์ Hull และ Meal) ก่อนเขียนโค้ดจริง
- **เขียนโปรแกรมและทดสอบ** ทยอยส่งเวอร์ชันตั้งแต่ปลายพฤษภาคมถึงกลางสิงหาคม 2024 คู่กับ **IO Check list** ที่เช็คทีละจุดกับตู้จริง
- **แผน Commissioning** Dry test 3 ถึง 4 วัน แล้วค่อย Trial กับวัตถุดิบจริง

2. **เลิกใช้ PUT/GET กับเครื่องที่คุยกันประจำ** เปลี่ยนเป็น PROFINET I-Device หรือ OPC UA ที่ไม่ต้องเปิดสิทธิ์ให้ใครก็อ่านเขียน PLC ได้
   เหตุผลเล่าไว้ใน [บทความ OT Security](/blog/ot-security-factory/)
3. **ปรับ In-flight อัตโนมัติ** ให้ PLC เรียนรู้จากน้ำหนักจริงของรอบก่อนๆ แล้วเลื่อนจุดตัดเอง แทนค่าคงที่ที่ต้องมาจูนใหม่เมื่อวัตถุดิบเปลี่ยน
4. **เก็บน้ำหนักทุกถุงขึ้นฐานข้อมูล** เวลา, Set point, น้ำหนักจริง, ไลน์ และ Alarm ของรอบนั้น ส่งขึ้น
   [Unified Namespace](/blog/unified-namespace-mqtt-ignition-grafana/) ให้ทีมผลิตดู Yield และย้อนตรวจได้ทุกถุง
5. **ทดสอบ Handshake กับ Digital Twin ก่อนเข้าไซต์** จำลองสถานีบรรจุ เซนเซอร์ และ Health bit แบบที่เล่าไว้ใน
   [บทความ Digital Twin](/blog/digital-twin-test-before-commissioning/) วัน Dry test จะเหลือไว้เช็คของจริง ไม่ใช่แก้ตรรกะ

## 5 บทเรียนที่จะเอาไปใช้กับงานต่อไป

1. **ชั่งในที่ที่ค่าน้ำหนักนิ่ง** แยกจังหวะชั่งกับจังหวะเติม ความแม่นมาจากการออกแบบกระบวนการ ไม่ใช่จากโหลดเซลล์อย่างเดียว
2. **ช้าลงก่อนถึงเป้า** 3 สปีดกับการเผื่อ In-flight ทำให้ได้ทั้งความเร็วและความแม่น
3. **ทุกสัญญาณระหว่างเครื่องต้องมีเจ้าของ** และต้องมี Health bit บอกว่าอีกฝั่งยังอยู่
4. **ตกลง Alarm ก่อนเขียนโค้ด** รายการ Alarm ที่ทุกฝ่ายเห็นด้วยตั้งแต่แรก ช่วยไม่ให้หน้างานเถียงกันว่าอะไรควรหยุดเครื่อง
5. **Flowchart คือสัญญา** ส่งให้ลูกค้ารีวิวก่อน แล้วเขียนโปรแกรมตามนั้น

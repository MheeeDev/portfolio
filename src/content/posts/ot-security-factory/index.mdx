## OT ไม่ใช่ IT ที่อยู่ในโรงงาน

หลายคนเริ่มจากเอาวิธีของ IT มาใช้ตรง ๆ แล้วเจอปัญหา เพราะสิ่งที่สองฝั่งต้องปกป้อง**ก่อน**ไม่เหมือนกัน

| | IT ในออฟฟิศ | OT ในโรงงาน |
|---|---|---|
| สิ่งที่สำคัญที่สุด | ข้อมูลต้องไม่รั่ว (Confidentiality) | **คนต้องปลอดภัย** และเครื่องต้องเดินต่อได้ (Safety, Availability) |
| อายุอุปกรณ์ | 3–5 ปี | 15–20 ปีขึ้นไป |
| Patch / Reboot | ทำได้ทุกเดือน | ต้องรอหยุดเครื่อง บางเครื่องไม่มี Patch แล้ว |
| ผลของการโจมตี | ข้อมูลหาย เสียเงิน | เครื่องเสีย ของเสีย สิ่งแวดล้อม และ**ชีวิตคน** |
| การสแกนหาช่องโหว่ | ทำได้ตลอด | สแกนแรง ๆ อาจทำให้ PLC รุ่นเก่าค้าง |

เพราะแบบนี้ OT Security จึงไม่ได้เริ่มจาก "ติดตั้งโปรแกรมป้องกันไวรัส" แต่เริ่มจาก**แบ่งพื้นที่และคุมทางเข้าออก**

### เรื่องจริงที่วงการจำไม่ลืม

- **Stuxnet (ค้นพบปี 2010)** มัลแวร์ที่แพร่ผ่าน USB ไปแก้โปรแกรม PLC ให้เครื่องเหวี่ยงเสียหาย ขณะที่หน้าจอยังแสดงค่าปกติ
- **โครงข่ายไฟฟ้ายูเครน (ธันวาคม 2015)** ผู้โจมตีเข้าระบบ SCADA แล้วสั่งตัดวงจรจากระยะไกล บ้านหลายแสนหลังไฟดับ
- **TRITON (2017)** มัลแวร์ที่เล็งระบบ Safety Instrumented System ของโรงงานปิโตรเคมี ซึ่งเป็นด่านสุดท้ายที่ปกป้องชีวิตคน
- **Colonial Pipeline (2021)** Ransomware โจมตีฝั่ง IT แต่บริษัทต้องหยุดส่งน้ำมันทั้งท่อเพื่อความปลอดภัย

ข้อสุดท้ายน่าคิดที่สุดครับ **OT ไม่ต้องโดนโจมตีโดยตรงก็หยุดได้** แค่ไม่มั่นใจว่าเชื่อใจระบบได้หรือเปล่า ก็ต้องหยุดแล้ว

## Purdue Model · แบ่งโรงงานเป็นชั้น

ก่อนจะล็อกอะไร ต้องรู้ก่อนว่าอะไรอยู่ตรงไหน **Purdue Model** แบ่งระบบในโรงงานเป็นชั้น ตั้งแต่เซนเซอร์ที่ Level 0 ไปจนถึงออฟฟิศที่ Level 4
ส่วนมาตรฐาน **IEC 62443** เพิ่มอีกสองคำที่สำคัญมาก

- **Zone** คือกลุ่มของเครื่องที่ต้องการความปลอดภัยระดับเดียวกัน
- **Conduit** คือทางเชื่อมระหว่าง Zone ซึ่ง**ต้องผ่านด่าน**เสมอ เช่น ไฟร์วอลล์ที่อนุญาตเฉพาะสิ่งที่จำเป็น

ลองเลือกว่าผู้บุกรุกเข้ามาทางไหน แล้วสลับระหว่างเครือข่ายแบนกับเครือข่ายที่แบ่ง Zone ดูครับ

<ZoneMap />

สังเกตกรณี USB ไหมครับ Segmentation ช่วยได้มาก แต่**ไม่ใช่ทุกอย่าง**
ภัยที่เดินเข้ามาด้วยมือคนจะอยู่ใน Zone ตั้งแต่แรก จึงต้องมีอีกหลายชั้นช่วยกัน ซึ่งเรียกว่า **Defense in Depth**

<Quote en="Segmentation stops the stranger at the gate. It does nothing about the USB stick already inside.">
Zone กั้น**คนแปลกหน้า**ได้ · แต่กั้น**แฟลชไดรฟ์ที่อยู่ข้างในแล้ว**ไม่ได้
</Quote>

## IEC 62443 ในหนึ่งหน้า

IEC 62443 เป็นชุดมาตรฐานความปลอดภัยของระบบควบคุมอุตสาหกรรม แบ่งตามบทบาทของแต่ละฝ่าย

| ส่วน | สำหรับใคร | เรื่องหลัก |
|---|---|---|
| **62443-2-1** | เจ้าของโรงงาน | โปรแกรมความปลอดภัยขององค์กร |
| **62443-3-2** | ทีมออกแบบระบบ | ประเมินความเสี่ยง และแบ่ง Zone / Conduit |
| **62443-3-3** | System Integrator | ข้อกำหนดของระบบ และ Security Level |
| **62443-4-1 / 4-2** | ผู้ผลิตอุปกรณ์ | การพัฒนาสินค้าให้ปลอดภัย และข้อกำหนดของอุปกรณ์แต่ละชิ้น |

ใน 62443-3-3 มีข้อกำหนดพื้นฐาน 7 ข้อ (Foundational Requirements) ที่เราชอบใช้เป็นเช็กลิสต์เวลาออกแบบ

1. **ระบุตัวตน** ทุกคนและทุกระบบต้องมีบัญชีของตัวเอง
2. **คุมการใช้งาน** แต่ละบัญชีทำได้เฉพาะสิ่งที่จำเป็น
3. **ความถูกต้องของระบบ** ข้อมูลและโปรแกรมต้องไม่ถูกแก้โดยไม่มีใครรู้
4. **ความลับของข้อมูล** ข้อมูลที่ข้าม Zone ต้องเข้ารหัส
5. **จำกัดการไหลของข้อมูล** ข้อมูลข้าม Zone ได้เฉพาะผ่าน Conduit
6. **ตอบสนองเหตุการณ์ได้ทัน** มี Log และมีคนดู
7. **ระบบต้องพร้อมใช้** มาตรการความปลอดภัยต้องไม่ทำให้เครื่องหยุด

แต่ละ Zone ยังมี **Security Level (SL)** บอกว่าต้องกันผู้บุกรุกระดับไหน

## ลงมือ: ล็อก UNS Lab ทีละชั้น

กลับมาที่ Lab จาก EP.04 ครับ เราจะใช้ข้อ 1, 2, 4 และ 5 ของ 62443 ล็อก Broker ทีละชั้น
ทุกอย่างอยู่ในไฟล์ Compose แยกที่ซ้อนทับไฟล์เดิม จะสลับกลับไปโหมดเปิดเมื่อไหร่ก็ได้

### ชั้น 1 · ปิดประตูหน้าบ้าน และให้ทุกระบบมีบัญชีของตัวเอง

```text
# mosquitto/secure.conf
per_listener_settings false

# Inside the zone: only containers on the lab network reach this port.
listener 1883

# The conduit: the only port the outside sees, and it is encrypted.
listener 8883
cafile   /mosquitto/certs/ca.crt
certfile /mosquitto/certs/server.crt
keyfile  /mosquitto/certs/server.key

allow_anonymous false
password_file /mosquitto/config/passwd
acl_file      /mosquitto/config/acl
```

บัญชีมี 4 ตัว แยกตามหน้าที่ ไม่มีบัญชีไหนใช้ร่วมกัน

```bash
mosquitto_passwd -b passwd tk101-sim  <password>
mosquitto_passwd -b passwd telegraf   <password>
mosquitto_passwd -b passwd scada      <password>
mosquitto_passwd -b passwd viewer     <password>
```

### ชั้น 2 · ACL ให้สิทธิ์เท่าที่จำเป็น (Least Privilege)

นี่คือหัวใจของบทความนี้ครับ **ทุกบัญชีทำได้แค่งานของตัวเอง**

```text
# mosquitto/acl
# The tank publishes its own values and only listens to its own commands.
user tk101-sim
topic write iae-lab/rayong/utilities/water/tk101/+
topic read  iae-lab/rayong/utilities/water/tk101/cmd/#

# The historian only reads data, never commands.
user telegraf
topic read iae-lab/+/+/+/+/+

# SCADA reads everything and is the only one allowed to send commands.
user scada
topic read  iae-lab/#
topic write iae-lab/+/+/+/+/cmd/#

# Dashboards and reports: read-only.
user viewer
topic read iae-lab/#
```

เห็นไหมครับว่าโครง Topic แบบ ISA-95 ที่ออกแบบไว้ใน EP.04 กลายเป็นเครื่องมือด้านความปลอดภัยไปด้วย
แยก `cmd/` ออกจากข้อมูลตั้งแต่แรก วันนี้เลยเขียน ACL ได้ในไม่กี่บรรทัด

### ชั้น 3 · TLS ที่ Conduit และไม่ให้พอร์ตภายในหลุดออกนอก Zone

```yaml
# docker-compose.secure.yml (excerpt)
services:
  mosquitto:
    ports: !override
      - "8883:8883"   # only the TLS port leaves the lab network; 1883 stays inside
```

ใบรับรองของ Lab ทำเองด้วย `openssl` เป็น CA ของ Lab หนึ่งใบ กับใบของ Broker ที่ระบุชื่อ `mosquitto` และ `localhost`
งานจริงควรใช้ CA ขององค์กร และกำหนดวันหมดอายุพร้อมแผนต่ออายุให้ชัด

### ผลทดสอบหลังล็อก

เราลองโจมตี Lab ตัวเองซ้ำทุกแบบ นี่คือผลจริงจาก Terminal ครับ

`MqttSecurityException: Not authorized to connect`

บทเรียนคือ**ทำรายการก่อนว่าใครต่อ Broker อยู่บ้าง** แล้วสร้างบัญชีให้ครบก่อนปิดประตู ไม่งั้นระบบที่ควรทำงานจะหยุดเอง ซึ่งขัดกับข้อ 7 ของ 62443 พอดี

</Callout>

## สิ่งที่ห้ามทำในนามความปลอดภัย

ความปลอดภัยที่ทำให้เครื่องหยุดเอง ก็คือการโจมตีที่เราทำกับตัวเองครับ

<Callout type="safety" title="Do no harm · กฎข้อแรกของ OT Security">
- **ห้ามสแกนเครือข่าย PLC แบบเต็มกำลังระหว่างเดินเครื่อง** อุปกรณ์รุ่นเก่าบางตัวค้างได้จากการสแกนธรรมดา ให้ใช้วิธีฟังเงียบ ๆ (Passive) หรือนัดช่วงหยุดเครื่อง
- **ห้ามเปิด Auto-update บนเครื่อง HMI ที่เดินเครื่องอยู่** ทดสอบ Patch บนเครื่องสำรองหรือ Digital Twin ก่อน แบบเดียวกับใน [EP.02](/blog/digital-twin-test-before-commissioning/)
- **ห้ามปิดพอร์ตหรือบล็อกทราฟฟิกโดยไม่รู้ว่าใครใช้อยู่** ทำรายการก่อนเสมอ อย่างที่เราเจอกับ Ignition ข้างบน
- **ห้ามให้ Interlock และ Safety ไปพึ่ง Network** UNS ล่มเมื่อไร PLC ต้องยังปกป้องเครื่องได้เหมือนเดิม
</Callout>

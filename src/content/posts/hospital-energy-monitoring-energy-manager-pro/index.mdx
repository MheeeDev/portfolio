## ระบบนี้ต่อกันยังไง

![ภาพวาดระบบ Energy monitoring จากซ้ายไปขวา ตู้ไฟเปิดฝาเห็นบัสบาร์ทองแดง L1 L2 L3 และ N ร้อยผ่าน CT วงแหวนสีดำ 3 ตัว สายเส้นเล็กจาก CT ต่อเข้า Power meter สามเฟสบนฝาตู้ที่แสดงแรงดัน 230 โวลต์ ต่อสาย LAN สีฟ้าไปที่ Network switch แล้วไปเครื่อง Server ที่รัน Energy Manager PRO หน้าจอแสดง Energy dashboard แบบใหม่ และมีแท็บเล็ตเปิดดู Dashboard ผ่าน Web browser](./system.webp)

<small>ภาพวาดประกอบ วาดจากภาพถ่ายหน้างาน ไม่ใช่ภาพถ่ายจริง และไม่ได้แสดงจำนวนตู้หรือขนาด CT จริง</small>

| ชั้น | อุปกรณ์ | หน้าที่ |
|---|---|---|
| วัดกระแส | CT (Current transformer) 3 ตัวต่อตู้ ครอบสาย L1, L2, L3 | ย่อกระแสหลายร้อยแอมป์ลงเหลือ 5 A ให้มิเตอร์อ่านได้อย่างปลอดภัย |
| วัดและคำนวณ | Siemens SENTRON **PAC5200** บนฝาตู้ | วัดแรงดันตรงจากบัส รวมกับกระแสจาก CT แล้วคำนวณ kW, kVAR, PF และสะสม kWh เอง |
| รับส่งข้อมูล | Ethernet ผ่าน Network switch ของอาคาร | ให้ Server อ่านค่าจากมิเตอร์ทุกตัวแบบ Modbus TCP |
| เก็บและคิดเงิน | **Siemens Energy Manager PRO** บน Server | เก็บค่าเป็นอนุกรมเวลา ตั้งสูตร TOU / TOD และทำรายงาน |
| ดูผล | Web client ของ Energy Manager PRO | ทีมอาคารเปิดดู Dashboard จาก Browser ได้ ไม่ต้องลงโปรแกรม |

หัวใจของงานนี้คือ **ตัวเลขทุกตัวต้องมาจากค่าที่วัดจริง** ครับ ไม่ใช่เอาบิลมาหารเฉลี่ย
มิเตอร์สะสม kWh ได้แม่นอยู่แล้ว สิ่งที่เราต้องทำคือให้ข้อมูลเดินทางมาถึงซอฟต์แวร์ครบ ตรงเวลา และคิดเงินด้วยสูตรเดียวกับที่การไฟฟ้าใช้

## หน้าจอที่ส่งมอบจริง

หน้า Dashboard ที่เราออกแบบใน Energy Manager PRO ตอนส่งมอบ (กลางเดือนธันวาคม 2024) วางเป็น 2 แถว
แถวบนเป็น **ค่าแบบ Real-time** แถวล่างเป็น **ค่าไฟที่คิดเป็นเงินแล้ว**

| Widget | แสดงอะไร |
|---|---|
| Total usage | กราฟแท่ง kWh ตามช่วงเวลา พร้อมค่า Median, Average และยอดรวม |
| Electricity consumed | kWh ของช่วงที่เลือก กับกราฟวงกลมแยก Wh, VARh, VAh |
| Current usage | เกจและตารางกระแสแยกเฟส L1, L2, L3 |
| Data TOD | หน่วยที่ใช้กลางวัน / กลางคืน อัตราต่อหน่วย และค่าไฟของช่วงนั้น |
| Data TOU | หน่วยที่ใช้ช่วง Peak / Off-peak อัตราต่อหน่วย และ **Cost Time of Use** เป็นบาท |
| Peak demand | กราฟ Demand ตามเวลา แยก Peak / Off-peak ให้เห็นว่าค่าสูงสุดเกิดตอนไหน |

ทุก Widget ผูกกับ **ตัวเลือกช่วงวันที่ด้านบนตัวเดียว** เปลี่ยนจากวันนี้เป็นทั้งเดือน ทุกตารางและทุกกราฟจะคิดใหม่ตามช่วงนั้นทันที
นี่คือฟีเจอร์ที่ทีมอาคารใช้บ่อยที่สุด เพราะเอาไปตอบคำถามแบบ "เมื่อวานที่เปิดห้องผ่าตัดเพิ่ม ใช้ไฟไปเท่าไหร่" ได้เลยครับ

## สูตรคิดค่าไฟมาตรฐาน

โรงพยาบาลขนาดใหญ่จัดอยู่ใน **ประเภทที่ 4 กิจการขนาดใหญ่** ของ กฟภ. (Demand ตั้งแต่ 1,000 kW หรือใช้เกิน 250,000 kWh ต่อเดือน)
ซึ่งมีให้เลือกคิดได้ 2 แบบ ตัวอย่างด้านล่างใช้อัตราที่แรงดัน 22–33 kV

**TOU (4.2.2) แบ่งตามช่วงเวลาในสัปดาห์**

| รายการ | สูตร |
|---|---|
| ค่าความต้องการพลังไฟฟ้า | **132.93 ฿/kW** × Demand สูงสุด (เฉลี่ย 15 นาที) ในช่วง Peak |
| ค่าพลังงานไฟฟ้า | **4.1839 ฿/kWh** × kWh ช่วง Peak + **2.6037 ฿/kWh** × kWh ช่วง Off-peak |
| ค่าบริการ | **312.24 ฿** ต่อเดือน |
| ค่า Power factor | **56.07 ฿/kVAR** × ส่วนของ kVAR สูงสุดที่เกิน 61.97% ของ kW สูงสุด |
| ค่า Ft | Ft ของงวดนั้น × kWh ทั้งหมด |
| รวมทั้งหมด | ทุกบรรทัดข้างบน × **1.07** (VAT 7%) |

**Peak** คือจันทร์–ศุกร์ 09:00–22:00 ส่วน **Off-peak** คือจันทร์–ศุกร์ 22:00–09:00 รวมเสาร์ อาทิตย์ และวันหยุดราชการทั้งวัน

**TOD (4.1.2) แบ่งตามช่วงเวลาในวัน ทุกวัน** ค่าพลังงานคิดอัตราเดียว 3.1471 ฿/kWh
แต่ค่า Demand คิด 285.05 ฿/kW จาก Demand สูงสุดช่วง Peak 18:30–21:30 บวก 58.88 ฿/kW เฉพาะส่วนที่ช่วง Partial 08:00–18:30 สูงกว่าช่วง Peak

<Callout type="tip" title="ทำไม Demand ถึงแพงกว่าที่คิด">
ค่า Demand คิดจาก **ค่าเฉลี่ย 15 นาทีที่สูงที่สุดเพียงครั้งเดียวของทั้งเดือน** ครับ ถ้าวันหนึ่งเปิด Chiller พร้อมลิฟต์และเครื่องมือหนักๆ ทับกันแค่ครึ่งชั่วโมง
ตัวเลขนั้นจะถูกคูณ 132.93 บาทไปทั้งเดือน การเห็นกราฟ Peak demand บนจอจึงสำคัญพอๆ กับการเห็น kWh เพราะแก้ได้ด้วยการเหลื่อมเวลาสตาร์ทเครื่อง
ไม่ต้องลงทุนอะไรเพิ่ม
</Callout>

## ลองเลือกช่วงเวลาเอง

ด้านล่างคือ Dashboard ที่เราออกแบบใหม่ให้ทันสมัยขึ้นจากหน้าจอที่ส่งมอบ ใช้ **ข้อมูลโหลดจำลอง** ของอาคารหนึ่งตลอดเดือนธันวาคม 2024
ส่วนอัตราและสูตรเป็นของจริงตามตารางข้างบน ลองกดเลือก **วัน สัปดาห์ หรือทั้งเดือน** หรือกำหนดเวลา **จาก–ถึง** เอง
แล้วดูว่าค่าไฟ, Max demand และวงแหวน KPI เปลี่ยนไปยังไง คลิกแท่งรายวันเพื่อกระโดดไปวันนั้นได้ และลองเปลี่ยนค่า Ft หรือระดับแรงดันดูครับ

<EnergyDash />

<Callout type="note" title="ไอเดียวงแหวน KPI มาจาก OEE">
ในโรงงานเราคุ้นกับหน้าจอ OEE ที่มีวงแหวน 3 วง Availability, Performance, Quality ครับ หน้านี้ยืมรูปแบบเดียวกันมาใช้กับพลังงาน
**Load factor** บอกว่าโหลดเรียบหรือพุ่งเป็นช่วงๆ (ยิ่งสูงยิ่งดี เพราะ Demand ไม่พุ่ง) **Power factor** บอกว่าใกล้โดนค่าปรับ kVAR แค่ไหน
และ **Off-peak share** บอกว่าใช้ไฟช่วงราคาถูกไปกี่เปอร์เซ็นต์ ดูแค่ 3 วงก็รู้ว่าเดือนนี้ควรไปแก้ที่จุดไหน
</Callout>

ตารางบิลด้านขวาล่างคิด **ทั้งเดือน** ทั้งแบบ TOU และ TOD จากข้อมูลชุดเดียวกัน แล้วบอกว่าแบบไหนถูกกว่า
เป็นคำถามที่ฝ่ายอาคารถามบ่อย และตอบได้ด้วยตัวเลขจริงเมื่อมีข้อมูลรายสิบห้านาทีครบทั้งเดือนครับ

## หน้างาน: CT ต้องถูกเฟสและถูกทิศ

ส่วนที่ใช้เวลาหน้างานมากที่สุดไม่ใช่ซอฟต์แวร์ แต่คือ **การต่อ CT ให้ถูก** ครับ Power meter คำนวณ kW จากแรงดันและกระแสของ **เฟสเดียวกัน**
ถ้าต่อสลับกันนิดเดียว ตัวเลขก็ผิดไปทั้งระบบ

1. **CT เฟสไหน ต้องเข้าช่องกระแสของเฟสนั้น** ให้ตรงกับแรงดัน L1, L2, L3 ที่ต่อเข้ามิเตอร์ ถ้าสลับ PF จะแปลก และ kW รวมจะต่ำกว่าความจริง
2. **ทิศของ CT (P1 → P2) ต้องหันไปทางโหลด** และขั้ว S1/S2 ต้องเข้าช่องให้ตรง ถ้ากลับด้าน เฟสนั้นจะขึ้น kW ติดลบ
3. **ตั้ง CT ratio ในมิเตอร์ให้ตรงกับป้ายของ CT** ไม่อย่างนั้น kWh จะเพี้ยนไปเป็นสัดส่วนเท่าๆ กันทุกค่า ซึ่งดูเผินๆ ไม่ออก
4. **เทียบกับมิเตอร์แบบคล้องวัด** ทุกเฟส ก่อนเชื่อตัวเลขบนจอ แล้วค่อยเปิดให้ซอฟต์แวร์เริ่มเก็บข้อมูลจริง

<Callout type="safety" title="ห้ามเปิดวงจรขั้ว S1/S2 ของ CT ตอนมีโหลด">
ถ้าสายด้านทุติยภูมิของ CT หลุดหรือถูกถอดในขณะที่สายหลักยังมีกระแสไหล CT จะสร้างแรงดันสูงมากที่ขั้วได้ ทั้งอันตรายต่อคนและทำให้ CT เสีย
ก่อนถอดหรือย้ายมิเตอร์ทุกครั้งต้อง **Short ขั้ว S1/S2 ก่อน** ตู้ที่ดีควรมี Terminal แบบ Shorting สำหรับวงจร CT ไว้เลยครับ
</Callout>

หลังทดสอบครบ เราพาทีมวิศวกรของโรงพยาบาลเดินดูตู้ทีละตู้ อธิบายว่ามิเตอร์ตัวไหนวัดโหลดอะไร แล้วกลับมาดูตัวเลขเดียวกันบน Dashboard
ให้เห็นว่าค่าบนจอกับค่าที่หน้าตู้ตรงกัน นี่คือขั้นตอนที่ทำให้ทีมอาคาร **เชื่อตัวเลข** และกล้าเอาไปใช้ตัดสินใจครับ

## ถ้าทำงานนี้ใหม่วันนี้ เราจะทำให้ทันสมัยขึ้นอีก 5 เรื่อง

1. **Dashboard แบบในตัวอย่างข้างบน** มีตัวเลือกช่วงเวลาแบบ Preset, วงแหวน KPI และตารางเทียบ TOU กับ TOD ในหน้าเดียว เปิดจากมือถือได้
2. **ใส่มิเตอร์ฝั่ง Solar** แยกให้เห็น **ไฟที่ผลิตเอง ใช้เอง และซื้อจากการไฟฟ้า** ตอนนี้มิเตอร์ฝั่งโหลดเห็นแต่ยอดที่ลดลง ไม่รู้ว่า Solar ช่วยได้เท่าไหร่
3. **แจ้งเตือนก่อน Demand จะทำสถิติใหม่** คำนวณค่าเฉลี่ย 15 นาทีแบบเลื่อนไปเรื่อยๆ ถ้าใกล้ค่าสูงสุดของเดือน ส่งข้อความหาทีมอาคารให้เลื่อนสตาร์ทเครื่องใหญ่
4. **ส่งข้อมูลขึ้น [Unified Namespace](/blog/unified-namespace-mqtt-ignition-grafana/)** ผ่าน MQTT ให้ระบบอื่นใช้ข้อมูลชุดเดียวกัน เช่น ระบบบริหารอาคาร หรือรายงานคาร์บอน
5. **ทำรายงานแยกต้นทุนตามหน่วยงานอัตโนมัติทุกเดือน** ห้องผ่าตัด, ICU, OPD, ห้องเย็นเก็บยา แต่ละหน่วยงานเห็นค่าไฟของตัวเองเป็นบาท แบบที่บิลใบเดียวไม่เคยบอก

## 5 บทเรียนที่จะเอาไปใช้กับงานต่อไป

1. **kWh อย่างเดียวไม่พอ ต้องเป็นบาท** คนตัดสินใจเรื่องงบประมาณเข้าใจเงินเร็วกว่าหน่วยไฟฟ้า
2. **ใช้สูตรเดียวกับการไฟฟ้า** ทั้ง Peak/Off-peak, Demand 15 นาที, Ft และ VAT ตัวเลขบนจอจะเทียบกับบิลจริงได้
3. **Peak demand คือเงินก้อนที่มองไม่เห็น** ต้องมีกราฟให้เห็นว่ามันเกิดตอนไหน
4. **CT ถูกเฟส ถูกทิศ ถูก Ratio** ก่อนเชื่อซอฟต์แวร์ ต้องเชื่อสายไฟก่อน
5. **ส่งมอบที่หน้าตู้ ไม่ใช่แค่หน้าจอ** เดินดูของจริงกับทีมผู้ใช้ แล้วตัวเลขบน Dashboard จะถูกใช้จริง

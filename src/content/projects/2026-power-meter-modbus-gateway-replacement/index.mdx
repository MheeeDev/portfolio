## Problem

A factory monitored its electricity use in Ignition from dozens of Schneider power meters, read over
RS-485 Modbus RTU through serial-to-Ethernet gateways. Readings from two distribution boards (MDB-2
and MDB-4) kept dropping out, and the old gateways were the first suspect. The work had to stay
invisible to the people using the screens: the existing Ignition licence, no PLC work, and no changes
to other databases, screens or reports.

## My role & scope

Automation engineer on the integrator's team:

- **Site survey** — confirmed which gateway served which board by unplugging one LAN cable at a
  time, and recorded every network and serial setting
- **Gateway replacement** — configured two Moxa MGate MB3270 units from the old settings, validated
  them and moved the Modbus wiring across
- **Proof of concept** — a four-meter test bench to separate gateway faults from line faults
- **Database move** — backup, restore, permissions and the Ignition database connection, remotely
- **Reporting** — a problem summary report for the client and the Phase 2 design

## Approach

- **Same IPs, same serial settings.** Ignition addresses each meter as `IP:502:SlaveID`, so a
  gateway configured with the old IP, baud rate and parity is invisible to the SCADA project.
- **Verify, don't trust the drawings.** The IP-to-board list was confirmed live, and serial settings
  were read from the meters' own displays.
- **Shrink the problem.** When readings stayed unstable after the swap, a four-meter bench on a
  short, correctly terminated line ran without a single dropout, which pointed at the existing line.
- **Root cause.** A failed meter at the head of the MDB-4 line was disabled in Ignition but still
  wired to the bus, where it disturbed the shared pair. SPARE and non-existent meters still had tags,
  so every polling cycle also waited on timeouts.

## Delivery

- **Phase 1** — two gateways replaced and validated; DB9-to-terminal adapters sourced on site when
  the new gateways turned out to have DB9 ports
- **Database move** — full backup and restore to the new SQL Server for both the application and the
  historian databases, then the Ignition connection switched; new rows confirmed in SSMS and hourly
  energy data continuous in Perspective
- **Phase 1.5** — materials delivered, problem summary report with site video, and an agreed next
  step to check the disabled meters remotely
- **Phase 2 design** — new gateways for all five boards, rewired RS-485 through terminals, and a
  five-day install and recheck plan

## Result

- Gateways replaced with no change to the Ignition project and no break in the energy data
- The fault located on the RS-485 line instead of in new hardware, so the client spends on rewiring
  rather than on more gateways
- Database running on the new server with other projects untouched
- A clear rule for the plant: a failed meter must be unwired from the bus, not only disabled in SCADA

## Problem

A brewery's empty kegs come back from the market stacked on pallets. On this line a vision-guided robot
lifts them off, one keg at a time, onto a keg conveyor, and the empty pallets go on to a stacker for the
forklift. The line still worked, but it ran on an ageing S7-300, and the signals between the PLC and the
robot were hard to read when something stopped.

## My role & scope

Controls engineer on the integrator's team:

- **PLC migration** — moved the program to a CPU 1515-2 PN with ET200MP I/O, keeping the original
  function structure and every sequence, wait and interlock
- **Conveyors** — six motors from pallet infeed to stacker, including the reversing keg conveyor,
  with light-curtain interlocks and a timer on every pallet transfer
- **PLC ↔ robot** — 16 bits each way over PROFIBUS DP (CM 1542-5), named in pairs and documented
- **HMI** — TP1200 Comfort screens for operation, maintenance, alarms and logging
- **Manual** — a 20-page operator manual in Thai covering every button and every alarm

## Approach

- **I/O table before code.** 64 inputs and 32 outputs named after their device and motor
  (`PH105_12M1`, `RS STACKER UP`), shared by the wiring team and the program.
- **Keep the structure the plant knows.** The old program was already split into functions by task;
  the new robot, alarm and logging parts were added as separate blocks around it.
- **One owner per bit.** Command bits from the PLC and status bits from the robot share names
  (CYCLE ON ↔ CYCLE ON, CH PROFIBUS ↔ OK PROFIBUS) so each handshake reads as a pair. A missing echo
  raises F15.
- **A clock on every move.** Pallet transfers that take too long raise F031–F043 instead of letting a
  motor drag a stuck pallet.

## Delivery

- TIA Portal V17 project, delivered in versions from late June to the end of July 2024
- HMI: overview with KEG 15/20/30/50 program selection, mode change with confirmation, user login,
  interlock page, I/O and robot I/O monitors, manual outputs per section, alarms, network diagnostics
- Setting page with run-hour targets per motor and a **Logging Step** export of the step history
- Punch list after the site walk-through fixed: forward/reverse motor status on screen and robot alarms
  shown on the empty-keg conveyor panel

## Result

- The line runs on supported hardware with the same behaviour operators already knew
- A stop now shows which step, which bit and which alarm, without a laptop
- Maintenance has motor run hours and a step log to work from

The full story in Thai, with the interactive cell and the handshake table, is in the
[blog article](/blog/keg-line-robot-profibus-s7-1500/).
